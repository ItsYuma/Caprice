# Resident speech

The microphone stays in the Tauri process. The weights stay in a child process. TypeScript receives a transcript through `Listener`.

The parent records, resamples to 16 kHz mono, and owns a state machine: `Idle` or `Live`. The first request moves `Idle` to a spawned worker and sends `load`. On `ready` the worker stays `Live`. A failed load or a broken pipe drops it and returns to `Idle`. A failed clip leaves the worker `Live`. Whole-clip turns use `drive` in `speech/phase.rs`. A streaming engine calls `warm` first so the weights are loaded before the microphone is hot.

The child is this binary started with `--speech-worker`. It reads one JSON object per line and writes one JSON object per line: `load`, `transcribe`, `feed`, `finish`, `ready`, `text`, `partial`, `error`. `feed` is incremental 16 kHz f32 little-endian PCM, base64, from `encode_pcm`. `partial` is committed text. `finish` returns `text`. `Engine` is the set of models that child can load. `CAPRICE_STT_ENGINE` selects the variant (`onnx` when empty). `CAPRICE_STT_MODEL` is the directory, or a GGUF for `parakeet`. A new speech model is a new `EngineKind`, a new `Engine` variant, and a match arm in `Engine::load`.

`Onnx` reads an int8 directory through `transcribe-rs` 0.3.12, so `ort` stays pinned to `2.0.0-rc.12`. `Bark` reads a `ParakeetForTDT` checkpoint (`config.json`, `tokenizer.json`, `model.safetensors`) through telmo and keeps the weights in bf16. Before each clip it prepends a quarter second of silence, which is what the publisher's runner does. The checkpoint we load is [Underdog Bark 3.0 Pro](https://huggingface.co/ConwayResearch/Underdog-Bark-3.0-Pro). The licence is CC BY-NC 4.0. Its Core ML and MLX packages are the same weights in other runtimes. `Onnx` and `Bark` still transcribe the whole clip when the talk key is released.

`Parakeet` is [Parakeet Unified English 0.6B](https://huggingface.co/nvidia/parakeet-unified-en-0.6b): FastConformer plus an RNN-T decoder, trained for offline transcription and buffered streaming. The weights are a GGUF from [handy-computer/parakeet-unified-en-0.6b-gguf](https://huggingface.co/handy-computer/parakeet-unified-en-0.6b-gguf), either that file or a directory containing one. They are not stored in git. The runtime is transcribe.cpp, linked in-process through the `transcribe-cpp` crate. That is the runtime Handy uses for model id `parakeet-unified-en-0.6b`. Caprice does not shell out to Handy. While the talk key is held and the engine is `parakeet`, the parent feeds new 16 kHz samples. The worker accumulates them and may answer `partial`. `speech_listen_stop` sends `finish` and returns that `text`, with no second full-clip pass. `transcribe` still runs one whole clip offline, so a caller without a stream still works.

Streaming uses the model card's low-latency row: left context 5.6 s, chunk 0.08 s, right context 0.08 s, 160 ms from chunk plus right context. Those are `LEFT_MS`, `CHUNK_MS`, and `RIGHT_MS`. Each chunk recomputes its left context over the PCM window. The encoder is not cache-aware. Text is committed only for audio that already has its right context. `finish` flushes the tail, including an utterance shorter than one chunk. The chunk schedule is `Utterance` in `speech/buffered.rs`. The native decoder is a transcribe.cpp buffered stream opened with that same row, so the RNN-T state and the chunked attention mask stay inside the runtime that implements this architecture.

Chat is HTTP. Spoken replies are a separate engine. Those choices are `chat-over-http.md` and `spoken-reply.md`.

Set aside: a TypeScript or Python process that owns the weights, Whisper, cache-aware streaming, and running the Bark TDT checkpoint under the name `parakeet`. One language loads speech models. The page reloads, and another language would be a second runtime to keep alive.
