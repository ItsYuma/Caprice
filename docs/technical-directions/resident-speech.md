# Resident speech

The microphone stays in the Tauri process. The weights stay in a child process. TypeScript receives a transcript through `Listener`.

The parent records, resamples to 16 kHz mono, and owns a state machine: `Idle` or `Live`. The first request moves `Idle` to a spawned worker and sends `load`. On `ready` the worker stays `Live`. A failed load or a broken pipe drops it and returns to `Idle`. A failed clip or feed leaves the worker `Live`. Whole-clip turns use `drive` in `speech/phase.rs`. `Follow::Clip` sends `transcribe` after `ready`. `Follow::Load` stops after `ready`, which is how a streaming engine is loaded when listening starts.

The child is this binary started with `--speech-worker`. It reads one JSON object per line and writes one JSON object per line: `load`, `transcribe`, `feed`, `finish`, `ready`, `text`, `partial`, `error`. `feed` carries incremental 16 kHz f32 little-endian base64, the same encoding as a clip. `partial` is the committed text so far and may be empty. `finish` returns `text`. `Engine` is the set of models that child can load. `CAPRICE_STT_ENGINE` selects the variant (`bark-stream` when empty, `bark`, `onnx`, or `parakeet`). `CAPRICE_STT_MODEL` is the directory, or a GGUF for `parakeet`. A new speech model is a new `EngineKind`, a new `Engine` variant, and a match arm in `Engine::load`.

`bark` and `onnx` answer `feed` with an empty `partial` and answer `finish` with `speech engine does not stream`. They still transcribe one full clip on release. `bark-stream` and `parakeet` accumulate `feed` samples and answer `finish` with `text`. Release does not also send `transcribe`.

While the microphone is hot and the engine streams, a feeder copies newly recorded samples and sends `feed`. The audio callback only appends. One feed is in flight at a time. If a feed is running, the feeder keeps the backlog and sends it on the next turn. It does not kill the worker to cancel. The parent resamples to 16 kHz and, until release, sends only samples whose value no longer depends on audio that has not arrived. On release the feeder sends the remaining tail and then `finish`. For those engines, `hear` is the tail after release, not the whole clip.

`Onnx` reads an int8 directory through `transcribe-rs` 0.3.12, so `ort` stays pinned to `2.0.0-rc.12`. `Bark` reads a `ParakeetForTDT` checkpoint (`config.json`, `tokenizer.json`, `model.safetensors`) through telmo and keeps the weights in bf16. `bark-stream` loads that same checkpoint. Before each clip telmo sees, the engine prepends a quarter second of silence, which is what the publisher's runner does. After that lead, a window is 10 seconds of left context, a 2 second center, and 2 seconds of right context. A center is committed only once the right context is present. Each window is a full-clip `transcribe` of that slice. Words that start in the right context stay uncommitted. A word already committed is replaced when the new slice revises it, and a word the slice only repeats is not appended again. The text at the end is that revised transcript. `finish` flushes the uncommitted tail without waiting for more right context. The utterance lives beside the loaded model in the worker.

The checkpoint we load for `bark` and `bark-stream` is [Underdog Bark 3.0 Pro](https://huggingface.co/ConwayResearch/Underdog-Bark-3.0-Pro). The licence is CC BY-NC 4.0. Its Core ML and MLX packages are the same weights in other runtimes.

`Parakeet` is [Parakeet Unified English 0.6B](https://huggingface.co/nvidia/parakeet-unified-en-0.6b): FastConformer plus an RNN-T decoder, trained for offline transcription and buffered streaming. The weights are a GGUF from [handy-computer/parakeet-unified-en-0.6b-gguf](https://huggingface.co/handy-computer/parakeet-unified-en-0.6b-gguf), either that file or a directory containing one. They are not stored in git. The runtime is transcribe.cpp, linked in-process through the `transcribe-cpp` crate. That is the runtime Handy uses for model id `parakeet-unified-en-0.6b`. Caprice does not shell out to Handy. `transcribe` still runs one whole clip offline, so a caller without a stream still works.

Streaming for `parakeet` uses the model card's low-latency row: left context 5.6 s, chunk 0.08 s, right context 0.08 s, 160 ms from chunk plus right context. Those are `LEFT_MS`, `CHUNK_MS`, and `RIGHT_MS`. Each chunk recomputes its left context over the PCM window. The encoder is not cache-aware. Text is committed only for audio that already has its right context. `finish` flushes the tail, including an utterance shorter than one chunk. The chunk schedule is `Utterance` in `speech/buffered.rs`. The native decoder is a transcribe.cpp buffered stream opened with that same row, so the RNN-T state and the chunked attention mask stay inside the runtime that implements this architecture.

Chat is HTTP. Spoken replies are a separate engine. Those choices are `chat-over-http.md` and `spoken-reply.md`.

A fresh clip is what lets a later Bark window replace a word. Also set aside: a TypeScript or Python process that owns the weights, and Whisper. One language loads speech models. The page reloads, and another language would be a second runtime to keep alive.
