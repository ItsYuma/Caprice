# Resident speech

The microphone stays in the Tauri process. The weights stay in a child process. TypeScript receives a transcript through `Listener`.

The parent records, resamples a full clip to 16 kHz mono, and owns a state machine: `Idle` or `Live`. The first clip moves `Idle` to a spawned worker, sends `load`, and on `ready` sends `transcribe`. `bark-stream` sends `load` when listening starts, then `feed` while the microphone is hot, and `finish` on release. The worker handle lives only inside `Live`. A failed load or a broken pipe drops it and returns to `Idle`. A failed clip or feed leaves the worker `Live`. The machine is `drive` in `speech/phase.rs`. `Follow::Load` stops after `ready`. `Follow::Clip` sends `transcribe`.

The child is this binary started with `--speech-worker`. It reads one JSON object per line and writes one JSON object per line: `load`, `transcribe`, `feed`, `finish`, `ready`, `text`, `partial`, `error`. `feed` carries incremental 16 kHz f32 little-endian base64, the same encoding as a clip. `partial` is the committed text so far and may be empty. `Engine` is the set of models that child can load. `CAPRICE_STT_ENGINE` selects the variant (`onnx` when empty, `bark`, or `bark-stream`). `CAPRICE_STT_MODEL` is the directory. A new speech model is a new `EngineKind`, a new `Engine` variant, and a match arm in `Engine::load`.

`bark` and `onnx` answer `feed` with an empty `partial` and answer `finish` with `speech engine does not stream`. They still transcribe one full clip on release. `bark-stream` accumulates `feed` samples and answers `finish` with `text`. The utterance lives beside the loaded model in the worker. Release does not also send `transcribe`.

While the microphone is hot and the engine is `bark-stream`, a feeder copies newly recorded samples and sends `feed`. The audio callback only appends. One feed is in flight at a time. If a feed is running, the feeder keeps the backlog and sends it on the next turn. It does not kill the worker to cancel. The parent resamples to 16 kHz and, until release, sends only samples whose value no longer depends on audio that has not arrived. On release the feeder sends the remaining tail and then `finish`.

`Onnx` reads an int8 directory through `transcribe-rs` 0.3.12, so `ort` stays pinned to `2.0.0-rc.12`. `Bark` reads a `ParakeetForTDT` checkpoint (`config.json`, `tokenizer.json`, `model.safetensors`) through telmo and keeps the weights in bf16. `bark-stream` loads that same checkpoint. Before each clip telmo sees, the engine prepends a quarter second of silence, which is what the publisher's runner does. After that lead, a window is 10 seconds of left context, a 2 second center, and 2 seconds of right context. A center is committed only once the right context is present. Each window is a full-clip `transcribe` of that slice. Words that start in the right context stay uncommitted. A word already committed is replaced when the new slice revises it, and a word the slice only repeats is not appended again. The text at the end is that revised transcript. `finish` flushes the uncommitted tail without waiting for more right context. For `bark-stream`, `hear` is the tail after release, not the whole clip.

The checkpoint we load is [Underdog Bark 3.0 Pro](https://huggingface.co/ConwayResearch/Underdog-Bark-3.0-Pro). The licence is CC BY-NC 4.0. Its Core ML and MLX packages are the same weights in other runtimes.

Chat is HTTP. Spoken replies are a separate engine. Those choices are `chat-over-http.md` and `spoken-reply.md`.

Set aside: keeping the TDT predictor state and decoding only the center frames. A fresh clip is what lets a later window replace a word.
